## 完整架构文档模板

用于新项目或大型功能的整体架构设计。

```markdown
# [项目/功能名称] 架构设计

## 1. 概述
### 目标
[这个功能/模块要解决什么问题]

### 范围
[包含什么，不包含什么]

### 关键指标
[成功标准：性能、可用性、可维护性等]

## 2. 技术选型

| 组件 | 选择 | 版本 | 理由 |
|------|------|------|------|
| 前端框架 | | | |
| 后端框架 | | | |
| 数据库 | | | |
| 缓存 | | | |
| 消息队列 | | | |

### 技术决策说明
[每个关键选型的 Decision → Why → Alternatives → Trade-off]

## 3. 系统架构

### 架构图 (文字描述)
[用文字或 ASCII 描述整体架构]

### 分层架构
- **表现层**: [前端技术和组织方式]
- **业务逻辑层**: [后端服务和业务模块]
- **数据访问层**: [ORM、数据库交互方式]
- **基础设施层**: [部署、缓存、消息队列等]

## 4. 项目结构
[目录树 + 每个目录/文件的职责]

## 5. 模块划分

### 模块依赖图
[模块间依赖关系]

### 模块职责
| 模块 | 职责 | 暴露接口 | 依赖模块 |
|------|------|----------|----------|

## 6. API 设计
[详见 api-design-guide.md 模板]

## 7. 数据库设计
[详见 database-design-guide.md 模板]

## 8. 开发顺序

### Phase 1: MVP [预计时间]
- [ ] 任务1 (依赖: 无)
- [ ] 任务2 (依赖: 任务1)

### Phase 2: 增强 [预计时间]
...

## 9. 技术债务与风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|

## 10. 可扩展性路线图
MVP → V1 → V2 各阶段的架构演进
```

## 模块设计模板

用于单个模块或功能的设计。

```markdown
# [模块名称] 设计文档

## 职责
[这个模块做什么]

## 接口
### 对外暴露
[其他模块可以调用的接口]

### 依赖
[这个模块依赖哪些其他模块]

## 数据模型
[相关的数据库表/字段]

## API 端点
[相关的 API]

## 关键逻辑
[核心业务逻辑流程]

## 边界情况
[需要特殊处理的情况]
```

## 技术决策记录模板 (ADR)

```markdown
# ADR-[编号]: [决策标题]

**状态**: [提议 / 已采纳 / 已废弃]
**日期**: [YYYY-MM-DD]

## 上下文
[为什么需要做这个决策]

## 决策
[我们选择了什么]

## 理由
[为什么这样选]

## 备选方案
### 方案 A: [名称]
- 优点: ...
- 缺点: ...

### 方案 B: [名称]
- 优点: ...
- 缺点: ...

## 后果
[这个决策带来的影响]
```
